# Paramify-CPP

**Paramify-CPP** is a lightweight C++14 library for **dynamic parameter management** using **YAML configuration files**, **command-line arguments**, and **runtime updates** — all with a clean, intuitive API.

It is designed for applications and libraries that need:
- declarative configuration
- CLI overrides
- runtime parameter access
- minimal dependencies

This project is the C++ counterpart of the original Python **Paramify** library.

---

## Features

- ✅ YAML-based parameter definitions
- ✅ Programmatic (code-defined) parameters
- ✅ Automatic CLI generation (`--help`, `--config`, flags)

  ```cpp
  double g = params["gain"];
  params["gain"] = 2.5;
  ```
- ✅ Strong runtime type checking
- ✅ CLI overrides without persistence
- ✅ Optional persistence back to YAML
- ✅ Header-only library
- ✅ C++14 compatible

## YAML Configuration Format

```yaml
name: my_app
description: Paramify C++ example

parameters:
  - name: audio_gain
    type: double
    value: 1.0
    scope: all
    description: audio gain multiplier

  - name: camera 
    type: group
    description: Camera parameters
    parameters:
      - name: enabled
        type: bool
        value: true
        scope: cli
        description: Enable camera

      - name: device_id
        type: int
        value: 0
      # scope omitted → runtime by default
  - name: display 
    type: group
    description: display parameters
    include: sub_params.yaml      
```

### Supported types
- `bool`
- `int` (internally `int64_t`)
- `double`
- `string`
- `list[bool|int|double|string]`

### Scope
- `cli` → exposed to CLI
- `runtime` → not exposed to CLI
- `all` → both

If `scope` is omitted, it defaults to **runtime**.

## Usage Examples

### 1️⃣ Load from YAML file
```cpp
paramify::Paramify params("params.yaml");

double gain = params["gain"];
params["gain"] = 2.5;
```

---

### 2️⃣ CLI-driven config (`--config`)
```cpp
paramify::Paramify params;
params.apply_cli(argc, argv);   // requires --config <file>

bool cam = params["use_camera"];
```

```bash
./app --config params.yaml --gain 3.0 --no-use-camera
```

---

### 3️⃣ YAML + CLI override
```cpp
paramify::Paramify params("default.yaml");
params.apply_cli(argc, argv);   // optional --config override
```

---

### 4️⃣ Programmatic schema (no YAML)
```cpp
paramify::Paramify params;

params.add_param("use_feature",
                 paramify::ValueType::Bool,
                 true,
                 paramify::Scope::All,
                 "Enable feature");

params.add_param("max_value",
                 paramify::ValueType::Int,
                 int64_t{4});

bool enabled = params["use_feature"];
params["max_value"] = int64_t{10};
```

---

### 5️⃣ Programmatic schema + CLI
```cpp
paramify::Paramify params;

params.add_param("gain",
                 paramify::ValueType::Double,
                 1.0,
                 paramify::Scope::Cli,
                 "Gain multiplier");

params.apply_cli(argc, argv);
```

```bash
./app --gain 2.5
```

---

### 6️⃣ YAML from string
```cpp
paramify::Paramify params;
params.load_from_yaml_string(R"(
parameters:
  - name: gain
    type: double
    default: 1.0
)");

double g = params["gain"];
```

## CLI Behavior

- `--help`  
  Automatically generated by **CLI11**, shows all available parameters.
- `--config <file>`  
  Loads YAML configuration.
- Boolean flags support:
  ```bash
  --use-camera
  --no-use-camera
  ```
- CLI values **override YAML defaults**, but are **not persisted**.

---

## Handling `--help`

CLI11 throws an internal exception after printing help.  
Recommended usage:

```cpp
if (!params.apply_cli_or_exit(argc, argv))
  return 0;
```

---

## Saving Back to YAML (Optional)

```cpp
params["gain"] = 2.0;
params.save_to_file();   // rewrites YAML defaults
```

> Note: YAML formatting/comments are not preserved.

---

## Error Handling

Paramify throws clear runtime exceptions:
- `ParamNotFound`
- `ParamTypeError`
- `ParamSchemaError`
- `ParamParseError`

These indicate configuration or usage mistakes early and explicitly.

---

## Design Philosophy

- YAML is **dynamic and authoritative**
- Explicit runtime behavior
- Library-friendly (no `argc/argv` in constructors)
- CLI is optional, not intrusive
